Question 2: Which other xv6 system call(s) could be made faster using this shared page? Explain how. 

1. getpid(): It returns current process ID and it can be shared as it is already
implemented and this helps avoid kernel trap.

2. uptime(): It returns system tick count, and it can be shared as it is frequently 
read but never written by user. This also helps avoid kernel trap for each read.

3. time(): It returns system time, and it can be shared as it it updates once per
tick. This allows fast user access to current time.

0x0000000000000000 → pte 0x...5B  
    User code/data page. Permissions: V, R, X, U, A.  

0x0000000000001000 → pte 0x...5B  
    Identical as previous entry.

0x0000000000002000 → pte 0x...D7  
    User data/stack page (read + write), permissions: V, R, W, U, A, D.  

0x0000000000003000 → pte 0x...07  
    Kernel-only mapping (read + write, no user access).  

0x0000000000004000 → pte 0x...D7  
    Another user data/stack page, ermissions: V, R, W, U, A, D.

0x0000003fffffd000 → pte 0x...13  
    USYSCALL page for fast getpid; user read-only (V, R, U).  

0x0000003fffffe000 → pte 0x...C7  
    TRAPFRAME page (kernel read/write, no user).  
    Used for saving user registers on traps.

0x0000003ffffff000 → pte 0x...4B  
    TRAMPOLINE page (read + exec, no write, supervisor only).  
    Used for entering or exiting user mode.
